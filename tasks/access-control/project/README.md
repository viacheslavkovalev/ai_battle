# Project Documents

Небольшой внутренний HTTP-сервис документов с проектными ролями. Python 3.11+,
SQLite из стандартной библиотеки; установка дополнительных пакетов не нужна.

## Запуск

Из каталога `project/`:

```sh
python3 -m service.app --database /tmp/project-documents.sqlite3 --port 8080
```

При первом запуске база создаётся из `service/seed.sql`. Существующая база
сохраняется, повторный запуск её не сбрасывает. Для чистого стенда используйте
новый путь к базе. Все данные фикстуры вымышлены. По умолчанию сервер слушает
`127.0.0.1`; тесты выбирают свободный порт автоматически.

```sh
python3 -m unittest discover -s tests -v
```

Каждый тест использует отдельную временную базу. Эти тесты проверяют часть
штатных сценариев и могут проходить при наличии дефектов в реализации.

## Пользователи стенда

механизм входа, выпуска и ротации токенов находится вне этого проекта.

| Пользователь | Токен | Finance (17) | People (29) |
|---|---|---|---|
| marina | `demo-marina-token` | editor | — |
| oleg | `demo-oleg-token` | viewer | — |
| irina | `demo-irina-token` | — | admin |
| pavel | `demo-pavel-token` | — | editor |

Документы: `2001` и `2002` принадлежат Finance, `3001` — People. Это начальные
данные; код должен поддерживать любое число проектов, пользователей и документов.

## Ожидаемое поведение

У каждого пользователя независимая роль в каждом проекте. Участники проекта
могут просматривать список его документов, читать и скачивать их. `editor`
и `admin` также изменяют заголовок и содержимое. `viewer` имеет доступ только
для чтения. `admin` действует в пределах проекта; глобальной роли администратора
нет. Пользователь без участия в проекте не имеет доступа к его документам.

Без токена и с неизвестным токеном API отвечает `401`. Для пользователя с валидным
токеном отсутствующий или недоступный проект/документ даёт `404` с одинаковым
сообщением соответствующего типа. Запрещённое изменение доступного viewer
документа даёт `403`; данные при отказе не меняются. Выдача списка проектов
возвращает только проекты пользователя, в том числе пустой список.

## API

Все ответы, кроме скачивания, — JSON в UTF-8. Ошибка: `{"error": "MESSAGE"}`.
Идентификаторы — положительные целые числа. Списки отсортированы по `id`.

| Метод и путь | Успешный ответ |
|---|---|
| `GET /health` | `200`, `{"status": "ok"}`, без токена |
| `GET /api/projects` | `200`, `{"projects": [{"id": 17, "name": "Finance", "role": "editor"}]}` |
| `GET /api/projects/{id}/documents` | `200`, `{"documents": [{"id": 2001, "project_id": 17, "title": "Budget draft"}]}` |
| `GET /api/documents/{id}` | `200`, объект с `id`, `project_id`, `title`, `body` |
| `GET /api/documents/{id}/download` | `200`, тело документа как `text/plain; charset=utf-8`, вложение `document-{id}.txt` |
| `PATCH /api/documents/{id}` | `200`, обновлённый объект с `id`, `project_id`, `title`, `body` |

`PATCH` принимает JSON-объект с одним или обоими полями `title`, `body`.
`title` — строка длиной 1–200 символов, не состоящая только из пробелов;
`body` — строка до 20 000 символов, может быть пустой. Остальные поля, неверные
типы, пустой объект или некорректный JSON дают `400`. Неуказанные поля сохраняются.
Максимальный размер тела HTTP-запроса — 65 536 байт; слишком большой запрос даёт
`400`. Идентификатор документа и его проект через API не меняются.

Пример штатного запроса:

```sh
curl -H 'Authorization: Bearer demo-marina-token' http://127.0.0.1:8080/api/projects
```
